# Migration map: old repo → ego2g1_v2

Directory-by-directory account of where everything in the original ego2g1 tree went —
including what was **deliberately dropped and why**, because the drops are the point of
the refactor: the old tree had five loose copies of openpi and zero dependency
manifests. When something below says "dropped", the code is still in the old repo
(read-only); nothing was destroyed.

|---|---|---|

## Dropped, deliberately

| old repo | why it does not come along |
|---|---|
| `openpi-zh/` | ZH's own 520 MB checkout with **three nested openpi copies** (`src/openpi`, `openpi_clone/src/openpi`, `openpi_zh/src/openpi`) and `/home/zh` absolute paths baked into its scripts. Nothing imports it; it exists as reference only. |
| `third_party/xr_teleoperate/` | Never imported by any of our code. Its one transferable idea — the IK temporal-smoothness cost + 4-tap weighted moving filter — **was adopted and measured** (26.5 → 3.8 rad/s² worst-joint accel RMS, see [jitter_root_cause.md](jitter_root_cause.md)); the idea moved, the 250 MB checkout doesn't need to. |
| `data_extraction_eef_elbow/` | One-off study: can IK track EEF **and** elbow? Answer measured and closed — the elbow residual has a **hard geometric floor of ~7–10 cm** (best mode: 8 cm L / 13 cm R) because the G1's upper arm cannot reproduce the human's; EEF-only tracking stays at ~0.1 cm. Conclusion recorded, code not carried. |
| `DEPLOY_SERVE_AUDIT.md`, `DEPLOY_SERVE_FIXES.md`, `VERIFICATION.md`, `audit_repro/` | Audit-session artifacts (already deleted in the old working tree). Their *fixes* were applied to the old deploy/serve code, which is exactly what `ego2g1/deploy` and `ego2g1/serve` port — the fixes live on in code, the paperwork doesn't. |
| `zh_deploy_inference/`, `zh_ego2g1_bridge/` | ZH-integration shims. The bridge served ego2g1 checkpoints to ZH's client but was **never hardware-tested** (arm/hand ordering assumptions unverified) — don't build on its conclusions. What survives is the *design lesson*: joint-space chunks are a first-class action mode in `ego2g1/deploy`, so no bridge is needed. |
| `episode_20_dashboard.html`, `MUJOCO_LOG.TXT` | Generated artifacts. Dashboards are re-generated by `ego2g1/data`'s dashboard stage. |

## Layout deltas worth knowing

- **No `src/` nesting**: `ego2g1/` is the one importable package at repo root, so
  `python -m ego2g1.…` works exactly like the old repo's invocations.
- **Teleop is a tool, not a package member**: it tests the retarget end-to-end but is
  not train/serve/deploy, so it lives in `tools/` with its `_vendor/` intact until the
  mechanical de-vendor (`tools/teleop/INTEGRATION.md`).
- **Machine state moved out of the fork**: the old `env.sh`/`infer_env.sh` lived inside
  `third_party/openpi/ego2g1/`; profiles now live in `envs/` and are documented in
  [environments.md](environments.md), including *why* the PPU box and robot PC cannot
  be uv groups.
